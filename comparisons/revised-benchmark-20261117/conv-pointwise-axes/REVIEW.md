# Independent review: `conv-pointwise-axes`

**Verdict: accepted for the frozen mathematical model case.** The replayed Lean theorem proves the complete rank-three (one spatial axis), forward, dense, same-type pointwise convolution rewrite for arbitrary independent input/kernel/output dimension-number permutations, with the stated Nat-exact value model and source-valid grouping guards. This is a new physically indexed adapter around the already available normalized pointwise/separable value law; it is not a proof of C++–Lean correspondence and does not close every semantic/numeric/rank variant of the retained XLA source record.

## Statement and source assumptions

I inspected `FREEZE.md`, `PointSpec.lean`, `PointProof.lean`, `PointControls.lean`, `cases.json`, `AUTHOR.md`, and the pinned source ranges listed below. The theorem `RevisedBenchmark.ConvPointAxes.verified : Goal` quantifies all six permutations for each of the input, kernel, and output role orders. For every legal output coordinate it proves output/input shape agreement; both generated output-to-source axis maps are inverse transports; all read indices are in bounds; the grouped old input address and kernel address equal the replacement addresses; and the finite computation equals the pointwise product. The goal retains the actual old group/batch address formula rather than assuming its group offset away.

The proof's `s.batches = 1` is properly **derived**, not introduced as a source guard. At `algebraic_simplifier.cc:11141–11147`, the simplifier requires input features and result features both equal `feature_group_count`, and kernel input features equal one. Forward shape inference sets result features to kernel output features (`shape_inference.cc:2193–2250`). Shape inference requires positive group counts and forbids both counts being nonunit (`:2446–2463`), and requires kernel output features divisible by batch-group count (`:2586–2605`). If batch-group count were greater than one, exclusivity forces feature-group count to one; kernel output features are then one, which cannot be divisible by that larger positive count. Thus batch-group count is one. Input-batch divisibility is still required (`:2609–2617`) and is represented in `Legal`.

The selected source branch has unit kernel extent, no stride/padding/dilation, no sparse RHS, no layout-sensitive mode, and same element types. At `algebraic_simplifier.cc:11123–11139`, the one-unit-kernel branch satisfies the spatial restriction and the window restrictions are explicit; `:11141–11147` supplies the pointwise feature guards. The code generates maps by assigning output batch/feature/spatial positions to corresponding input/kernel positions (`:11150–11179`), then conditionally transposes each operand (`:11181–11198`). The maps have output-axis-to-operand-axis orientation, as represented by `permutation`/`inverseRead`. For rank three, a sorted map is identity and skips the transpose; the same map semantics apply to the executed transpose branch. The model's independent `Order` values cover all 216 triples.

The evaluator's indexing matches the old side of the model: `hlo_evaluator.cc:5965–5984` computes batch-group size, feature-group sizes and indices; `:5993–6038` computes tap/window coordinates and reversal; `:6040–6065` adds the output-batch and batch-group offsets, feature index, kernel output-feature index and channel index before multiplying/accumulating. Under this packet's derived batch-group count one, feature-group size one, and unit tap, those indices reduce to the model's output-feature-selected input feature, original output batch/spatial coordinate, and the corresponding kernel output feature with zero input-feature/tap. The source window-reversal formula is also a no-op for an extent-one kernel, though this packet freezes the no-nontrivial-reversal pointwise label.

`CreateBroadcastSequence` at `hlo_instruction.cc:2442–2496` retains every positional dimension whose extent equals the target, including equal singleton dimensions; it only drops a mismatching extent-one source axis, reshapes the retained axes in increasing order, then broadcasts using those positions. This agrees with the model's equality-based `broadcastRead` and the `retained`/`unsqueeze` lemma, including coincident singleton feature dimensions. The source reduction list is empty when the kernel spatial extent is one (`algebraic_simplifier.cc:11164–11178`), so the multiply is not followed by reduce/reshape (`:11206–11217`).

The mathematical contract is Nat exact and does not characterize IEEE rounding, signed zero, NaNs, integer overflow, or conversion behavior. It covers nonnegative Nat tensor payloads and all static extents in its domain, including zero batch/spatial extents. Feature/group extents are positive by `Legal`. The zero-output-domain cases are handled vacuously for coordinate reads while the shape/permutation facts remain proved. No argument is made that the native evaluator or TensorRight observes exactly this Nat model in every machine type.

## Case accounting and remaining convolution scope

This closes one **complete mathematical model case** at the frozen scope `SimplifyConvToMultiply/pointwise-000`: rank three, one spatial axis, exact Nat observations, no casts, and unit-kernel pointwise geometry. It is not simply the inherited normalized single-channel identity: the new proof handles physical dimension numbers, derived batch-group behavior, output shape, legality of concrete operand reads, and equal-axis/singleton kernel broadcast.

It does not by itself close the broader XLA lexical/source record for other ranks, other numeric contracts, mixed-type conversion paths, sparse inputs, backward convolution, or non-pointwise/reduction geometries. The existing `model-audit/convolution-remaining-gate.md` lists the 12 source variants and keeps source-adapter/cast obligations separate; its broader family remains open. In particular, a rank-three Nat model result does not prove the source's floating-point accumulation behavior or machine-overflow cases. No speedup or C++–Lean correspondence claim follows.
