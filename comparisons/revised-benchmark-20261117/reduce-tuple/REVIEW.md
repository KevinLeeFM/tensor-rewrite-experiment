## Exact mathematical coverage

- `RevisedBenchmark.TupleReduce.empty` quantifies over every nonempty tuple arity `k+1`, every family `A : Fin (k+1) → Type`, every static keep/reduce plan, whole-state binary reducer, actual initializer and input tuple. Each slot is observed at every bounded output coordinate. From zero input count **or** zero output count it proves equality with the tuple of broadcasts of the corresponding actual initializers in the original output shape. With an output coordinate, zero input forces fiber length zero and the fold returns the actual initializer. A zero output shape has no coordinates. There is no reducer law or component-independence hypothesis.
- `RevisedBenchmark.TupleReduce.sameCount` fixes the plan, reducer, initializer and equal-count witness before quantifying over **all input tuples**. Uniform equality to the ordered reshapes of the respective data inputs is equivalent to zero output cardinality or a left identity on the **whole state**. At positive output cardinality every fiber is singleton, with the same canonical logical index as reshape. The theorem's global left identity is necessary for the universal-input claim. A particular tensor may agree despite a nonidentity reducer when its actual elements are fixed. That is a different question from the frozen uniform tuple theorem. At zero output cardinality, reduced axes need not have unit extent.
- Packing a component tuple into a tensor of dependent states and unpacking it transpose two independent function arguments `c` and `j`. In the forward direction the proof instantiates the quantified tuple input by projecting an arbitrary packed input. This ranges over all packed states, so the constant tensor used in `SameCountExact.uniform_iff` can observe any whole state. In the reverse direction it applies the packed theorem to the input obtained by transposing the actual tuple. Combined with the definitions of reshape and constant, the explicit congruences preserve slot and index. The old theorem is specialized to a dependent function type and has no tuple-separability assumption. The branch comment assumes identity, while the condition checks counts and layout, so the model's identity requirement cannot be credited as a runtime filter. No associativity argument is required for the model's empty or singleton fibers. A model mismatch with a nonidentity initializer tests the necessity of the premise. It does not show a legal HLO counterexample. The Lean plan describes bounded logical indices with natural-number extents. It does not check the source's integer/overflow range, dynamic metadata, bitcast/layout legality, floating-point representation/exception behavior, graph mutation or status, effects, or C++–Lean correspondence. In particular, reducer shape inference permits some floating precision mismatches, with a separate mixed-precision verifier option, whereas broadcast and reshape require matching element types.
