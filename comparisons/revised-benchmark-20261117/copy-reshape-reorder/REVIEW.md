## Statement and value semantics

`CopySpec.copy` fills each destination physical slot by reading the source slot for the same logical coordinate. `old` models the optional prior copy, reshape as a value-preserving logical remapping, then final copy. `replacement` either forwards the memory when copy omission is permitted or copies to the aligned layout, then either forwards that buffer for a raw bitcast or logically copies into the final layout. `CopyChain.verified` composes and cancels these copies. The new proof reduces both sides to the same source-to-final logical copy. For the raw branch it uses the explicit premise `aligned.address row = final.address row` for every logical row. Thus the theorem compares the complete output functions, including the model's empty and singleton finite domains; it is not data-dependent.

The source check is directionally consistent with that premise. In `sources/xla/xla/shape_util.cc:1785ff`, `ShapeUtil::ReshapeIsBitcast` first requires arrays, explicit layouts, same element type (unless explicitly ignored), and equal element count. For nonempty inputs its documentation says the check establishes equal physical position for each paired logical index; it returns true immediately for zero elements. This supports the dense equal-width address interpretation, not a source-to-Lean correspondence theorem. `AlignLayouts` at `shape_util.cc:2058ff` searches for an output layout making that predicate true and may fail; it also handles degenerate dimensions specially. The model assumes an aligned layout is already supplied and deliberately does not verify that C++ routine.

## Source guard and scope audit

At `algebraic_simplifier.cc:2007–2094`, this reordering is under `options_.is_layout_sensitive()`, matches `Copy(Reshape(...))` with the one-user constraints, and optionally matches `Reshape(Copy(...))`. It computes the old and aligned/new hardware-bitcast predicates. The actual rewrite choices are: old non-bitcast/new bitcast (new bitcast, with either copy kept or omitted); old non-bitcast/new non-bitcast only when a prior copy exists (new reshape, with either copy kept or omitted); and old bitcast/new bitcast only when a prior copy exists (new bitcast, with either copy kept or omitted). Old bitcast/new non-bitcast is not selected. Copy omission additionally requires a prior copy and `Shape::Equal().IgnoreMemorySpaceInLayout()(new_copy_shape, copy_before->operand(0)->shape())`. A raw bitcast requires source `ReshapeIsBitcast(new_copy_shape, copy->shape())`.

The source also applies the 10% peak-shape-size guard: it rejects when `after > 10 * before / 9`. Under this packet's static, equal-element-count, equal-element-width array model, each counted array has the same `n * element_width` byte size (ignoring integer overflow and layout padding), so the four abstract output choices have costs `before/after` of `2n/n`, `3n/2n`, `2n/n`, or `3n/2n` element-sized arrays, respectively; each satisfies the guard for positive `n`, and both totals are zero at `n=0`. The model does not encode this guard or actual shape-byte arithmetic. Tiling compatibility, memory-space transfers/effects, shape metadata, dynamic shapes, sharding, lowering and use-count effects are excluded as stated in `FREEZE.md`; the result must not be read as covering those details.

`ReorderControls.lean` has a positive omitted-copy/raw case and a positive kept-copy/logical-output case, plus a wrong-address raw negative control. These are useful checks, but do not witness all four source choices. In particular, no concrete source-shaped witness is provided for either kept-copy/raw or omitted-copy/logical, and the abstract `Dense n` model has no rank/dimension tuple with which to establish the old/new `ReshapeIsBitcast` premises for any particular XLA shape. The model's Boolean `raw` is not the complete old/new source branch condition. Therefore branch nonvacuity and source reachability for all four combinations remain unverified; I do not count this packet as four separately demonstrated source executions. The theorem itself proves the stated abstract equality for every valuation satisfying its two guards, including cases beyond the source's selected rewrite branches.

The corrected freeze is coherent with that interpretation and explicitly discloses cost/use-count/options and implementation exclusions. Earlier `copy-layout-chain` is reused, not new proof effort; the packet's prior historical `Copy(Reshape)->Reshape` composition is distinct from proving the complete source guard or all four branch witnesses. No claim of XLA execution, performance, or complete source rewrite coverage follows.
