# Pad-fold historical theorem reuse: final residual audit

## Verdict

Retain two historical mathematical-theorem reuse rows, one for `HandleReduceWindow/pad-fold-direct` and one for `/pad-fold-convert`. `PadWindow.reduce_fusion` and `convert_reduce_fusion` are genuinely complete ordered-list/fold equivalences for their declared model; they preserve every padding entry and therefore require no reducer laws. This is useful exact mathematical evidence for the finite/nonnegative Pad/window model, not a closed source record. XLA's `ReduceWindow` evaluator skips out-of-bounds positions, so transferring the theorem to the evaluator requires an ordered-fold deletion result under right identity of the init, plus a mapping of the evaluator's valid event order. The historical theorem does not prove that bridge.

The pinned HLO operation contract says initial values must form an identity under the computation and notes arbitrary evaluation/reassociation (`sources/xla/docs/operation_semantics.md:4161–4165, 4225ff`). This supplies the relevant semantic restriction for an admitted source reducer; the evaluator behavior is explicit in `hlo_evaluator.cc:4043–4046, 5052–5062`: accumulator starts at init and the reducer callback is invoked only for in-bounds positions. For a fold whose omitted explicit Pad positions contain init, the directly relevant law is `operation accumulator init = accumulator`. Thus credit the historical arbitrary-operation theorem and separately disclose that source applicability uses the HLO reducer contract; do not characterize the evaluator as folding an init value at each skipped coordinate.

## Source mapping

The two records map to `HandleReduceWindow`'s common Pad-fold block at pinned `algebraic_simplifier.cc:9919–10112`, with the actual replacement at `:10104–10112`. Direct mode matches `ReduceWindow(Pad(input, fill), init)`. Converted mode matches `ReduceWindow(Convert(Pad(input, fill)), init)` and constructs a conversion of the unpadded input before the new window. In both paths the code checks `pad_value == reduce_init_value`, or for differing constants checks equality after converting the Pad literal to the init shape (`:9986–10013`). It rejects negative/cropping Pad (`:9980–9984`) and rejects simultaneous interior Pad and a base-dilated original window (`:9972–9978`). The converted path may be declined by its one-nontrivial-dimension padding-ratio heuristic (`:9929–9959`). Both paths must fall through the `combined_bcast || rw_bcast` alternative (`:10079–10102`); those replacements are separate broadcast-sequence cases, not credited by these rows.

The code adjusts window low/high by original base dilation times Pad edge amounts and sets base dilation to `1 + interior_padding` only when such padding is present (`:10019–10033`). Historical `PadWindow.reduce_fusion` exactly matches the abstract relation when explicit Pad fill and the model's implicit invalid-sample fill are the same. It proves equality of the entire contribution list, then folds the same ordered list with arbitrary operation and initializer. `map_pad`/`convert_reduce_fusion` preserve the actual converted fill with no homomorphism law; `convert_initial_fusion` substitutes init only when `convert fill = initial`. The source's constant-literal check is a concrete admission test for that value equality, not a proof of the scalar conversion or reducer semantics.

## Important source/model residuals

1. **Skip-padding transfer.** `ReductionWindow.values` materializes a fill value at every position whose sample is `none`; the historical `reduce_fusion` proves those same filled lists on both sides. The pinned evaluator instead starts from init once and enumerates only valid indices. An old explicit Pad fill is a valid tensor element and is reduced; after fusion, its corresponding original-input position is out of bounds and is skipped. Matching Pad fill to init alone does not prove these folds equal for an arbitrary operation. Under the HLO contract's identity law, delete each such init token using right identity. A useful missing theorem is an ordered filtered-fold lemma showing that, for the `sample_compose`-related old/new kernel streams, removing every token equal to init preserves the fold when `∀ acc, op acc init = acc`; instantiate it at result type β for conversion. This must preserve order and deal with interleaved padding/dilation holes. No such complete evaluator transfer is present in the inspected PadWindow declarations. Existing `ReductionWindow.foldl_replicate_fixed` only removes a leading repeated block under a fixed-point premise; it is not the needed arbitrary-position/filter lemma.

2. **Empty-input high-padding formula.** The mathematical model derives an empty-safe high edge. `docs/pad-window-fusion.md` records that for empty original input with nonempty padded extent it is `h + H*b - (b-1)`, while the ordinary nonempty simplification is `h + H*b`. The C++ block shown here unconditionally sets `new_high = h + H*b` (`:10027–10029`). The early zero-element exit checks the ReduceWindow input shape (the already padded tensor) and output (`HandleReduceWindow` near `:9585`); it does not, in the inspected block, explicitly exclude an empty pre-Pad input whose edge padding makes the Pad result nonempty. Therefore the source's empty-input domain/shape-inference behavior needs separate reconciliation before crediting the model's empty-safe cases as source-applicable. For example, the 1-D geometry `n=0, L=H=1, b=2, kernel=1, stride=1` distinguishes the model's correction from the simple C++ high-edge formula. This is a source-formula audit observation, not a fresh HLO verifier or runtime counterexample; no test/build was run.

3. **Other scope.** The source also has Pad/convert matching, literal equality, backend support exclusions, optional broadcast replacement, and heuristic admission. Source records additionally include typed numeric/observation behavior and source graph constraints not established by the generic theorem. `reports/pad-window.json` explicitly says whole-benchmark records closed is zero, independent review pending, and benchmark correspondence uncertified. Keep the outcome ledger unresolved for both records.
