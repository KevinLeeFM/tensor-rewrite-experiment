# DUS to Pad with a tuple or concatenate start operand

At pinned XLA `e58e523b11f1fde802a493a776d158007486e1bf`, the tuple form has no shape-admitted profile. The concatenate form has a rank-zero exception to the positive-rank obstruction. It specializes the already checked scalar value law.

**Shape admission.** The ShapeVerifier passes DUS `index_shapes()` to shape inference, using its default `allow_scalar_indices=true`. The instruction enumerates each operand starting at operand 2 and takes its outer shape; it never flattens tuples. A first rank-one index selects the legacy branch, requiring exactly one integral array of shape [operand rank]. Otherwise the normal branch requires exactly rank-many compatible integral scalars. Setting the flag false forces the legacy branch. The proto reader independently admits the three-operand legacy rank-one form. **HandleDynamicUpdateSlice/pad-tuple.** Neither mode admits a tuple of integer constants, including an empty tuple. In the default mode the rank test reads the first operand's dimensions before validating it as an array. The shape accessor documents its array precondition and its fallback CHECK requires a buffer. No graceful diagnostic or runtime result for malformed input is assumed. Explicit vector mode checks ExpectArray. Both the legal empty index vector and the legal empty list of scalar starts differ from an empty tuple operand. **HandleDynamicUpdateSlice/pad-concatenate.** A legal concatenate needs at least one operand, a dimension within its rank, equal input ranks, and returns that same rank. The DUS vector form therefore requires rank-one concat children. At positive operand rank the handler immediately tests concat child zero with ConstantScalar, which requires a constant rank-zero array; a length-one constant vector also fails. Concatenating actual scalar literals has no legal concat dimension. The handler calls GetFirstInteger only after that test. Scalar-list mode cannot use a scalar-result concatenate. Host offloading and the enable/async gates further restrict matches. **Rank-zero exception and exact substitution.** Consider a non-async scalar s32 DUS whose base is a scalar-to-scalar broadcast of fill, update is a scalar parameter, and one index operand is concat along dimension 0 of two s32[0] arrays. The concat result is s32[0], the exact vector shape required for rank zero under either flag. With the rewrite enabled and no host-offload pattern, direct handler inspection finds operand 2 and recognizes concatenate. Its zero-iteration axis loop tests no literals. It emits Pad(update, fill) with an empty configuration, legal on a scalar. In existing `RevisedBenchmark.UpdateConstantPad.verified` specialize rank to 0, extent and start functions to empty functions on Fin 0, payload to the chosen scalar type, and read to the unique scalar update. Fit, bounds and coverage are universal over an empty axis type. The sole output coordinate selects that scalar in both calculations. No literal extraction or new clamp theorem is required. The distinct valid scalar-list encoding with zero starts has no operand 2, so this example specifically uses the legacy rank-one vector.
