## Row findings

1. **`dot-empty` — retain with the narrowed finish/zero condition.** `HandleDot` (lines 4378–4405) declines operands beyond two and layout-sensitive mode, then replaces an empty output/lhs/rhs with a result-shaped broadcast of result-type zero. `dot_empty_output`, `dot_empty_lhs`, and `dot_empty_rhs` prove the corresponding normalized contraction results equal a constant `finish zero`; the empty output case is vacuous over indices, while empty operands imply empty contraction fibers. The row now explicitly requires the source result-zero behavior to match `finish zero`. The outcome ledger still leaves `HandleDot/empty` unresolved because concrete dimension/precision/finish correspondence and graph mapping are not closed.

2. **`outer-product` — retain as theorem reuse, not five accepted records.** `HandleDot` reaches the no-contracting-dim branch only after empty handling, with layout-insensitive mode, `SupportedDotPrecisionConfig(..., false)`, `enable_dot_to_multiply_rewrite`, and no lhs contracting axes (lines 4405–4410). HLO dimension-number verification is needed to infer the matching rhs condition. `RewriteAsMultiplyDotWithZeroLhsContractingDim` (lines 3884–3920) normalizes axes, converts operands to result element type as needed, broadcasts and multiplies. `dot_no_contract_of_finish_identity` proves the single-product contraction only when the explicit `finish (add zero value) = finish value` premise holds. It does not establish the source dimension-number/plan bridge, conversions, precision or finish behavior. The source ledger marks all four casts variants as unresolved partial evidence and the delegation label as unresolved/no attempt evidence. The row is retained as one shared theorem link covering five labels, with those source obligations explicit.

3. **`outer-zero` — retain only as a profile refutation, not a source disproof.** `ZeroMacProfile.negative_zero_incompatible` and `zero_bits_differ` are exact bit-vector certificates for the narrowly stated one-MAC signed-zero profile, with no axioms. The native replay receipt shows an actual slow evaluator/handler/pass bit difference on the negative-zero diagnostic and says `fp_diagnostic_is_source_refutation: false`; its report leaves backend permissions pending. Therefore the row's `disproved` outcome is limited to the constrained arithmetic/observation profile. It is not a source-level disproof or a general HLO implementation claim. The row overlaps two source IDs already listed by `outer-product` and contributes no new distinct label.

4. **`conv-empty` — retain with the preceding-helper fallthrough condition.** `HandleConvolution` first runs optional `ScalarMultiplyReduction`, then replaces a zero-element input or filter with a scalar zero like the convolution output (lines 11223–11236). The row now credits the empty branch only when the earlier helper leaves the convolution in place. `convolve_empty_spatial_input` covers live padded outputs; `convolve_empty_kernel` and `convolve_no_channels` cover empty reduction fibers in the factored static semiring model. The source branch is specifically for an empty input/filter array; a zero per-group channel claim applies only when valid shapes make that operand empty. The outcome ledger leaves the complete source record unresolved pending convolution descriptor/group/window-to-plan correspondence and the earlier helper behavior.

5. **`scatter-empty` — retain with the actual compatibility guard.** `HandleScatter` first requires every update array to have zero elements (lines 10237–10246), then calls `ReplaceInstructionIfCompatible` with scatter operands. That helper skips instructions with control predecessors, checks shape compatibility (including tuple component counts/shapes), and preserves sharding/frontend attributes (lines 861–905). In the model, empty batch or window extents create no events, so `empty_components`/`scatter_empty` return the original base tuple without reducer assumptions. The outcome ledger still leaves `HandleScatter/empty-updates` unresolved because source update/index/component mapping and replacement/API conditions are not fully established.
