## Mathematical checks

`run` interprets each intermediate copy/reshape stage as a materialization preserving the common logical row number and placing that row at that stage's address bijection. Its list induction proves `run src dst stages data = copy src dst data` for every finite `stages`, including the empty sequence. `raw_verified` then uses equality of source and destination physical addresses at every logical row to show that the complete old output buffer equals the original data buffer, i.e. the result of the raw endpoint bitcast in this model. The endpoint condition is intentionally stronger than necessary for some empty cases; at `n=0` it is vacuous and both functions have empty domain. No intermediate-layout equality is assumed. `forward_verified` proves the pointwise equation at every destination address: a logical copy read at `dst.address i` returns `data (src.address i)`. This is logical-value forwarding, not buffer identity.

The controls exercise a three-stage nontrivial layout sequence, a wrong-endpoint-layout negative example, a logical copy across different orders, and the empty case. These are examples only; the generality comes from the compiled list-induction theorem, not the sample. The earlier `CopyChain.verified` is precisely reused copy composition/inversion; the new contribution is induction over an arbitrary finite list of layout stages and the distinct logical-forwarding observation.

## Source mapping and limits

The terminal helper is `AlgebraicSimplifierVisitor::BitcastingOperandOfReshapeOrCopyChain` at `algebraic_simplifier.cc:825–841`. It is active only for the layout-sensitive pass, starts at the current instruction's operand, and walks through `kReshape`/`kCopy` operands while `ReshapeIsBitcast(operand->shape(), instr->shape())` is false. It returns the first upstream candidate satisfying that endpoint predicate; a non-reshape/non-copy barrier returns null. `HandleCopy` calls it at `:1984` and replaces the root copy with a bitcast at `:1987–1988` when the selected operand exists, except when the root copy itself changes memory space (`:1973–1983`). `HandleReshape` calls it at `:7193–7196` and similarly replaces the root reshape. Thus `ChainGoal` models the logical values of a selected old path of finite reshape/copy stages and the endpoint raw bitcast test, not the search procedure, barriers, use-count, sharding, or source graph mutation.

`ShapeUtil::ReshapeIsBitcast` in `shape_util.cc:1785ff` requires array shapes, explicit layouts, same element type unless explicitly ignored, and equal element count. Its implementation/documentation checks preservation of physical linear positions for corresponding logical linear positions; for zero elements it returns true directly. With the packet's common byte-aligned element type and dense layout assumption, this is the physical-address equality represented by `ChainGoal`. Intermediate shapes/ranks are erased but preserve the common logical row by reshape/copy semantics. The packet does not model tiled/padded layouts, element-width conversion, dynamic shapes, sharding, backend lowering, aliasing, or the search's successful selection predicate.

Memory-space handling is a relevant boundary: the root `HandleCopy` explicitly avoids the chain-bitcast replacement when that root copy crosses memory spaces, while `HandleReshape` has no analogous root-copy check and the helper itself walks copies without testing their memory-space transitions. Therefore a source application must be restricted to paths where removing the traversed materializations is valid for memory placement (or otherwise establish that placement has no semantic consequence). The freeze discloses memory-space effects as excluded; this review does not infer that all arbitrary cross-space intermediate copies are safely eliminated. The model proves values only.

For the separately frozen forwarding claim, `SameShape` is layout-sensitive `ShapeUtil::Equal` but layout-insensitive `ShapeUtil::Compatible` (`algebraic_simplifier.cc:623–634`). `HandleCopy`'s compatible-removal path is guarded by sharding/root conditions at `:1965–1971`, then calls `ReplaceInstructionIfCompatible`; that helper checks control predecessors, `SameShape`, and preserves sharding (`:867–884`). The theorem matches the logical values under compatible dimensions/type while allowing different dense orders. It says nothing about retaining a copy's physical placement or aliasing effect.
