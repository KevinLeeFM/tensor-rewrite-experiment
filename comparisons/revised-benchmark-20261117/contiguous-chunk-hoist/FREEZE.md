# Reshape–transpose–reshape contiguous chunk hoist

One logical case for the successful FindContiguousChunks/HandleReshape delegation. Finite arbitrary ranks. Input reshape dimensions are the concatenation of nonempty consecutive input-axis groups in source axis order. Their permutation gives the output order of the transpose, preserving axes within each group. Associated common-factor output extents are exactly the products of group extents; these are the actual source's returned blocks. The inner reshape operand may have any equal-volume static shape; it is observed by logical row-major cell. Payloads arbitrary. This parameterizes a successful block decomposition, not the extractor or cost/shape policy. Sorted source block starts and output-to-sorted map are determined by the input-axis segmentation and this permutation, independent of offset equality. No contiguous-layout or backend correspondence claim.

Freeze ChunkSpec.Goal before proof. It quantifies over every coordinate of the output shape, compares the original output flat position to the fully expanded transpose-output coordinate, bounds each digit, then compares the original inner-reshape flat offset (expanded digits scattered back to input block order) to the emitted inner-reshape flat offset (one digit per sorted block). Original and emitted independently pack digits at different ranks. Empty extents have no complete output coordinate, product-one axes are retained, and rank-zero scalar has empty digit vector. The source may separately preempt zero/identity shapes before calling the helper. Require the [24]→[2,3,4]→[4,2,3]→[4,6] witness, wrong-order control and a multi-block non-self-inverse order check.
