## Exactly what is proved

`RevisedBenchmark.BroadcastReduceSingle.proved` at `7725b5b6156fc776ca0673483c2030abcf02994f` has type `Goal`: for each `α : Type`, plan, pure total `operation : α → α → α`, `initial : α` and `input : Tensor plan.inputShape α`, an input or output element count of zero implies `reduceTensor plan operation initial input = Tensor.constant initial` at `plan.outputShape`. The shared result shape is built into the dependent types. `Plan` recursively keeps or removes any set of axes, with arbitrary finite rank and natural extents including zero. Well-formed source axis sets are interpreted as keep/reduce tags in input-axis order. For these extents, a finite product is zero exactly when some extent is zero. A rank-zero scalar has product one, so scalar shape alone does not trigger the guard. The model has no requirement on the initializer expression producing the supplied value or on the data and reducer beyond the declared types. ## Limits on stronger claims

This value model treats input, accumulator, initializer and result as a common scalar carrier. It covers all scalar types and reducers of that declared homogeneous model, including any chosen scalar representation as logical data. It does not encode runtime dtype conversion, floating exception flags, dynamic dimension bounds versus runtime sizes, layouts, sharding, control/effect behavior, or graph mutation acceptance. Source shape inference removes the same axes and also propagates dynamic flags. Those flags are ignored here. The source zero check uses recorded extent values and does not mean “runtime extent zero” for a positive recorded bound. Extending the result to all source verifier/option combinations would also have to reconcile `VerifyReducerShape` using `CompatibleIgnoringFpPrecision` for the initializer and input arguments, `HandleReduce` permitting the separate mixed-precision verifier option, and `HandleBroadcast` requiring exact operand/result element-type agreement. The helper inserts no conversion. This is a concrete boundary on the stronger claim, without a tested source counterexample or reachability claim. The graph/API work would need a separate specification even for homogeneous static HLO.
