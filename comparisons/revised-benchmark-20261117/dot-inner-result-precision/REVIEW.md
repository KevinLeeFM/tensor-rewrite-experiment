# Independent review: inner-dot result precision

**Verdict: accept as one complete counterexample in the frozen typed mathematical model.** It is distinct in mechanism from `nested-dot-round`: the old inner BF16 result is rounded/stored before the outer dot, while both reordered dots request the old outer F32 result type. The two source orientations are witnesses for one precision-change case, not two distinct mathematical cases. They overlap the same `AssociativeReorderNestedDot` source exits already represented by the F32 accumulation-order case.

## Statement and replay

The frozen target is the negation of value preservation for each direct matrix-chain orientation under a strict cost-ratio guard. In the lhs-inner witness, dimensions `(m,k,n,p)=(8,2,8,2)` give old `(A B) C` cost 512 and new `A (B C)` cost 128. In the rhs-inner witness `(2,8,2,8)` gives 128 versus 512. Thus each exceeds the source's default threshold of 2 with non-unit dimensions. The model rounds BF16 loads and the old inner result, compares defined observations at a valid output coordinate, and has one nonzero product path. The counterexample is therefore caused by intermediate precision, not a changed sum order.

The frozen witness uses BF16-representable inputs 129, 129, and 1. The exact product 16641 is not BF16-representable at that magnitude; BF16 round-to-nearest-even gives 16640. The old expression returns 16640 after its inner BF16 result, while the replacement keeps the inner result in F32 and returns 16641. Lean proves both guarded refutations and all controls by `decide`; `#print axioms` reports `[propext]` for the refutation theorem. Fresh replay with the pinned Lean 4.35 binary passed all six modules, including checksum verification, in 2.375 seconds total. Per-module compiler times are recorded in `review.log`.

The packet's controls are relevant: removing the intermediate narrowing returns 16641 on both parenthesizations; replacing 129 by exactly representable 128 makes the old and new result 16512; and an off-path output coordinate is zero in both orientations. These establish non-vacuity and localize the discrepancy. The proof uses an explicit finite nonnegative integer-valued arithmetic model with BF16 rounding and the previously checked F32 rounding helper; it is not a general IEEE theorem.

## Source check

I inspected the pinned `sources/xla/xla/hlo/transforms/simplifiers/algebraic_simplifier.cc` implementation of `AssociativeReorderNestedDot` and `HandleDot`, `shape_inference.cc`, and `hlo_verifier.cc`. In the nested-dot rewrite, both `MakeDotHlo` calls receive `dot->shape().element_type()`, i.e. the old outer result type; the old inner dot retains its own BF16 result. `InferDotOpShape` honors its preferred result element type, and `ShapeVerifier::HandleDot` supplies the declared result type as that preference. The verifier's mixed-precision operand check allow-lists `kDot`; its ordinary shape comparison checks inferred versus declared output shape, not a same-type restriction on dot operands. Thus BF16 operands with F32 dot results are source-admissible under these shape/type checks. The pinned simplifier options proto gives the associative-reordering threshold a default of 2.0. The rewrite also requires associative reordering enabled and layout-insensitive handling; the frozen standard dense rank-2 profile satisfies the direct matrix shape geometry. The source preserves the dot precision config on both emitted dots.

This is source-level admissibility, not evidence that a particular compilation pipeline enables the option, that a backend accepts or executes this exact schedule, or that native output exhibits these values. The source's strict configurable cost test is represented by the frozen default-threshold assumption. No native execution or backend schedule is claimed.

## Scope and limits

This is one new precision-boundary model case, with two orientations. It is not an additional independent source rule and should not be added as two cases. The mathematical result does not establish all possible BF16/F32 dot chains, negative values, subnormals, infinities, NaNs, overflow, alternate operand precision configurations, batching, or general IEEE behavior. It does not establish a C++–Lean correspondence theorem, pass reachability in an end-to-end module, or a runtime bug. The earlier `nested-dot-round` result concerns F32 sequential summation and remains a separate model mechanism; the generic exact-semiring theorem does not subsume this narrowed intermediate.
