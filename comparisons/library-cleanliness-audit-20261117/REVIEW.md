# Targeted reusable-library cleanliness review

**Verdict:** the seven custom modules in the union of the five held-out proof baselines contain ordinary logical tensor/index definitions, two generic bounds proofs, and explicitly named specialized models; no target rewrite equality or unapproved axiom was found in those modules. Representative historical shared lemmas include both genuinely reusable geometry and intentionally rewrite-specific proof families. No code cleanup is justified by this sample. This is not a blanket audit of the 109-module paper closure or the whole 271-file maintained library.

Coordinator inspected all seven files and the direct held-out call sites at parent revision `280278f8150e53e73c1cc2e8bb4257864b030490`; a separate fresh Luna reviewer independently inspected the three representative suspicious examples and the unsigned-decoding boundary below. No source or proof files were edited. The finite known-contamination guards and earlier held-out independent import reviews are supplementary evidence, not substitutes for a universal semantic audit. File hashes for the selected surfaces are in `inventory.json`.

## Independently checked suspicious cases

* `DynamicIndexValue.lean:12–18` defines `unsignedValue := bits.toNat` separately from `evaluatorUnsigned64 := bits.toInt`, documented as an observed conversion in the pinned evaluator on the test host. `UnsignedIndexBoundary.lean:15–36` explicitly proves their clamping results disagree for high-bit u64 values. `NestedUnsigned64.lean:5–7,17–25` uses the second function for a disclosed host-profile diagnostic, not a backend contract. The two held-out DynamicSlice goals accept decoded `Int` starts and never call either decoder; they cannot establish native decoding or portability. Keeping the explicit diagnostic is safer than silently substituting either interpretation or changing frozen imports.
* `Theory/ArithmeticFamily.lean:35–64,74–134` explicitly encodes a closed collection of particular expression-tree rewrites; `Theory/ArithmeticFamilyProof.lean:39–50` case-splits the family and proves their tensor equalities using commutative-ring laws. This is **rewrite-family proof logic**, not a generic arbitrary-operator correctness theorem, though it is reused across multiple cases. It does not take an assumed target equality; the independent reviewer inspected the left/right definitions and proof. `comparisons/tensorright-v1/Add.lean:22–44`, `ScalarArithmetic.lean:20–90`, and `Logical.lean:76` instantiate it. Exact `[CommRing α]` excludes interpreting the result as unrestricted IEEE arithmetic. `rewrite_in_context` at `ArithmeticFamilyProof.lean:52–59` is ordinary pure-function congruence, not effectful context preservation.
* `Theory/PadWindow.lean:16–39,49–93` defines an independent Pad and derived window shapes. `Theory/PadWindowProof.lean:15–42` proves sample composition and contribution fusion through axiswise geometry and option cases, without assuming the desired equality or a scalar algebra law. Its common fill is explicit; `values_fusion` and `reduce_fusion` preserve the ordered values and actual initializer at lines 44–63. `comparisons/tensorright-v1/PadConvolution.lean:55–80` consumes it for one convolution-specific terminal proof. The sampler/geometry lemmas are reusable across that family, while the specialized application is correctly identified as a case proof.
* `signed_shift` is actually **in the paper comparison packet**, `comparisons/tensorright-v1/Remainder.lean:17–26`, not a generic `Theory.Remainder.signed_shift` declaration. It is a reusable scalar fact under the explicit `sameSign` condition for truncating remainder; `shifted_iota` derives that guard and `shifted_scalar` receives it explicitly (lines 48–73). `unguarded_shift_refuted` at lines 75–77 demonstrates why the guard cannot simply be dropped. This corrects the shorthand attribution in `comparisons/tensorright-v1/INFRASTRUCTURE.md`, which names it as `Remainder.signed_shift` without specifying its paper-comparison namespace. No circular target equality was found.

The independently reviewed source has no apparent need for a semantic cleanup. Moving the host-specific decoder, or moving the finite rewrite-family rules to another namespace, would change frozen module hashes and import closure without fixing a demonstrated defect; consider that only as a separately measured API migration. Existing protected frozen files and prior worktrees remain untouched.

## Coverage, residuals and verification

The bounded review covers every declaration in the seven small held-out baseline modules, the actual named held-out consumers, and the three sampled historical proof paths above. It does not certify all declarations, assumptions or call sites in the remaining paper-closure modules, upstream Mathlib/Std, every translation, all optional TensorRewrite files, or C++ correspondence. The paper closure includes substantial other domain-specific and rewrite-specific logic by design; it should not be described wholesale as a purely general library. An audit of the remaining modules would require a separately bounded inventory and risk-based review.

The independent fresh Luna review was read-only, approximately four minutes active; exact start/end and overlap are unavailable. The coordinator used read-only source/call-site inspection, hash inventory and lexical checks. No Lean replay was performed in this review because no mathematical or protected source changed; prior frozen goal, axiom and replay records remain in each case packet. No new theorem, benchmark or speedup claim follows.
