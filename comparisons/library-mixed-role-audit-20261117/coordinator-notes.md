# Coordinator: public roots and concrete boundaries

`reachability.py` checks the 42 frozen file hashes and follows syntactic `TensorRewrite.*` imports from `TensorRewrite.lean`, `TensorRewriteTheory.lean` and `TensorRewriteLibraries.lean`. All 42 are reachable from at least one root. These are environment-level import paths, not proof that every declaration is publicly re-exported or used by a theorem. Exact per-root results and hashes are in `reachability.json`.

## Actual mixed source-shaped rewrite logic in foundational slice shape

`TensorRewrite/Pilot/SliceShape.lean:15–32` defines static slice `Axis`, `elementCount` and `IsWellFormed`. The same public module defines two source-shaped transformations at lines 38–53, `removeRedundantStride` and `reorderReverse`. `Pilot/SliceIndexBounds.lean:3,12–27` imports SliceShape for the well-formedness/bounds theorem; `Pilot/IndexMaps.lean:3–4,34–42` then imports those bounds for generic static slice indexing. Thus this ordinary model import transitively exposes source-rewrite-specific logic. The transformations are not general preservation theorems: `Pilot/EmptySliceRefutation.lean:14–55` constructs a legal empty axis and proves that both replacements can fail the retained zero-extent `IsWellFormed` condition. This is a model certificate; source/backend behavior is separate.

A possible future separation is to introduce a foundational slice-shape core containing the axis/count/well-formedness definitions and have bounds/indexing import that core; keep the old public entry point as a compatibility facade containing or re-exporting the two named transforms, and update the refutation to import the transformation surface. The exact public module visibility and old names must be preserved and checked, and all affected source/import hashes and frozen acceptance packets must be regenerated or separately preserved; the proposal has not been implemented or Lean-checked. Merely re-exporting the transforms from the core would retain the unwanted dependency. This is an organization improvement, not evidence that existing generic theorems assume the bad transforms are valid.

## Host diagnostic mixed into generic index values

`Pilot/DynamicIndexValue.lean:12–21` places mathematical signed/unsigned decoders and the explicitly host-profiled `evaluatorUnsigned64` alongside general `clampStart`. The latter is imported by `DynamicIndexBounds.lean:3` and through `DynamicIndex.lean:4`, whereas `NestedUnsigned64.lean:17–25` and `UnsignedIndexBoundary.lean:15–36` are actual diagnostic consumers of the host interpretation. The previous independent review confirmed the host decoder is not used by the held-out mathematical-Int-start proofs. One could use a core values/clamping module and compatibility facade plus a separate diagnostic module, but preserve Lean names and update/refreeze affected consumers; that migration likewise needs targeted kernel/axiom/negative-control replay and independent recheck. No source changes are made in this audit.

## Broadcast axis ordering and uniqueness

`Pilot/IndexMaps.lean:17–32` requires only vector length, per-element range and shape extents. For rank two to rank two, an all-zero dimension vector is representable and repeats an output axis; a reversed vector is also in range. No uniqueness or ordering follows from the definition alone. This map still gives a well-defined logical coordinate projection, and equality theorems parameterized over every such map can be mathematically stronger than the subset corresponding to source-legal Broadcasts; neither situation proves source correspondence.

The explicit higher-level boundaries vary: `Theory/BroadcastWindowIndex.lean:16–44` proves `axesMap_strictMono` for that construction; `Theory/UnitAxisLemmas.lean:86–112` proves generated axes strictly increasing; `comparisons/heldout-transpose-broadcast/Spec.lean:14–26` independently requires both original and remapped arrays ordered. By contrast, `comparisons/tensorright-v1/Broadcast.lean:15–33` and `Theory/ArithmeticBroadcast.lean:18–27` quantify any range-checked map and prove logical reindex equations without an ordering premise. No premise should be silently inferred from the generic `BroadcastAxes` type. Any proposed source-level validity API must require exactly the inspected source's actual constraints, with explicit adoption at relevant callers, rather than changing the meaning of existing logical projection theorems.

Pinned `sources/xla/xla/service/shape_inference.cc:3979–4003,4024–4029` defines `InferBroadcastShape` for `BroadcastInDim`, checks rank/length/range and rejects dimensions that are not strictly increasing. The pinned source file SHA256 is `e55b7a4f46b2e6ac157ac6918fff06078c78c7e865f8a24b5da8c259d932c5e6`. This source reading supports the boundary: model projections permit a strictly larger set of maps than this source validity check. It does not establish C++–Lean correspondence or that every other HLO construction takes this path.

`InferBroadcastShape` also permits an operand dimension of one where the corresponding output dimension differs (`shape_inference.cc:4005–4014`), whereas `IndexMaps.broadcastIndex` requires each mapped extent equal. Thus the whole model domain is not a strict superset of source-legal Broadcasts: it is broader in axis-map validity and narrower in this extent relation. Assess each theorem and caller separately.

## Affine gather inside window semantics

`Theory/ReductionWindow.lean:77–103` also places an affine crop/stride gather alongside ordered window reduction. It is tied to `ReductionWindow.Plan`, so the independent review's suggested split is not automatically a clean independent module boundary. Actual consumers include `ReductionWindowLemmas.lean:79–80`, `ReductionWindowAlgebra.lean:70–87`, `SlicePadFactor.lean:65–98`, and a counterexample at `ReductionWindowCounterexamples.lean:45`. Any proposed separation first needs a dependency design preserving the existing plan, namespaces and lemmas, plus compatibility and replay; no move is recommended solely from this co-location.
