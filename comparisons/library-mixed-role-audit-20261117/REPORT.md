# Forty-two mixed-role library modules: bounded classification

**Gate result: all 42 frozen paths have evidence-bearing role classifications; no path is unresolved for this classification task.** This is not an exhaustive proof audit of all declarations or a certification that the entire reusable library is clean. Two fresh independent Luna reviewers inspected disjoint Pilot (19) and Theory (23) groups; the coordinator reconciled every row and frozen source hash, checked root reachability, and independently investigated selected high-risk assumptions and callers. No second independent semantic review of every individual row was performed.

[`classification.json`](classification.json) contains, for each file, the reviewer's actual role, summary, line references, target-specific dependencies and assumptions, representative consumers, explicit inspection limit, preserved SHA256 and syntactic root reachability. [`reconcile.py`](reconcile.py) checks the 42-file set, prior inventory hash, source hashes and mandatory evidence fields and regenerates the JSON to stdout. The classification is **16 semantic-model modules, 8 generic or operation-specific helper modules, 9 rewrite-specific proof modules and 9 mixed modules**. These describe predominant file roles, not mutually exclusive semantic properties of every declaration. The 19/23 reviewer files and high-risk findings are recorded separately in [`pilot-review.md`](pilot-review.md), [`pilot-review.json`](pilot-review.json), [`theory-review.md`](theory-review.md), and [`theory-review.json`](theory-review.json).

All 42 are in the syntactic transitive import closure of at least one of `TensorRewrite.lean`, `TensorRewriteTheory.lean`, and `TensorRewriteLibraries.lean`; see [`reachability.json`](reachability.json). Root reachability does not prove a declaration is publicly re-exported or used in a particular proof. Direct maintained and paper-packet importers come from the earlier frozen 109-module inventory; an import is not proof-term use. The other 67 historical closure modules were not reclassified in this pass.

## Concrete architectural findings

* **Source-shaped transforms in a foundational module.** `Pilot/SliceShape.lean:15–32` defines a slice axis, its element count and well-formedness; lines 38–53 also define `removeRedundantStride` and `reorderReverse`. Bounds and generic indexing transitively import this module, while `Pilot/EmptySliceRefutation.lean:14–55` uses the transforms in checked empty-slice model counterexamples. This is actual rewrite-specific logic co-located with a reusable semantic foundation, not evidence that the indexing theorems assume those transforms correct. A possible separate core plus backward-compatible transformation facade is outlined in [`coordinator-notes.md`](coordinator-notes.md); maintaining public names/import visibility, preserving archived packets, and retesting/refreezing affected consumers are mandatory before implementing it.
* **A host diagnostic shares a generic index-value module.** `Pilot/DynamicIndexValue.lean:12–21` places the named host-profiled `evaluatorUnsigned64` beside mathematical decoders and `clampStart`. The earlier independent review found the host interpretation differs on high-bit values and is not used in the held-out mathematical-Int-start proofs. A possible core/diagnostic module split needs the same compatibility, affected-closure replay and hash safeguards; do not silently change either interpretation.
* **Window and affine gather.** `Theory/ReductionWindow.lean:16–63,77–103` defines ordered window folds and a separate affine gather, but that gather depends on the same window `Plan` and is actually used by `ReductionWindowLemmas`, `ReductionWindowAlgebra`, `SlicePadFactor`, and a counterexample. A split may be worth design work; co-location alone does not justify moving it or claiming independence.

The reviewed source includes expected rewrite-specific work under shared `Theory/` paths. For example, `ArithmeticBroadcast.lean` proves a family of concrete exact-ring rewrite equalities, `NumericalField.lean` and `NumericalReal.lean` prove domain-specific identities, and `ReductionAlgebra.lean` proves operator-conditional reductions. They are identified as proof modules rather than described as neutral general-purpose foundations. The classification exposes imports and premise boundaries; it does not assert a proof is valid solely from its label.

## Broadcast ordering and extent boundary

`Pilot/IndexMaps.lean:17–32` checks vector length and each dimension's range and requires mapped input/output extents equal, but does not require axis order or uniqueness. Thus repeated or reversed in-range axis maps are representable. The logical `Broadcast` equalities in `comparisons/tensorright-v1/Broadcast.lean:15–33` and `Theory/ArithmeticBroadcast.lean:18–27` quantify over that broader class of maps, whereas the generated axis construction in `Theory/BroadcastWindowIndex.lean:16–44` and `UnitAxisLemmas.lean:86–112` proves strict ordering and the held-out transpose/broadcast statement explicitly requires it.

The pinned `shape_inference.cc:3979–4003,4024–4029` checks `BroadcastInDim` dimensions are strictly increasing, while lines 4005–4014 also permit an input extent of one mapped to a different output extent. Accordingly the Lean projection has a **broader map domain but a narrower mapped-extent relation** than this source check; neither full domain contains the other on these facts alone. The source file's SHA256 and exact scope appear in `coordinator-notes.md`. This source reading is not a proof of source-to-model correspondence, and does not imply that any particular source caller violates its own guards. An optional source-validity wrapper should be designed separately and only after checking its intended source contract; existing logical theorems should not silently acquire stronger hypotheses.

## Evidence and residuals

The reviewers read their assigned files, imports and selected callers, with per-file inspection limits. Classification is not a comprehensive proof-term/axiom or source-semantics audit; external libraries, compiler reachability, C++ correspondence, all other modules, and uninspected callers remain open. The reviewer-reported direct-import relationships are syntactic, not verified declaration calls. One Theory reviewer report says no worker/reviewer overlap occurred; it was written from that worker's perspective, while both reviewers ran concurrently at the coordinator level. Their exact active and wall intervals were not instrumented; no sum or productivity claim is supported.

All 42 frozen hashes and the prior inventory hash were verified. No Lean source, dependency pin or protected artifact changed, and no build or replay was run. No actual code cleanup is claimed. Proposed moves require a separate isolated change, targeted Lean/axiom and downstream controls, frozen-hash management and independent recheck.
